# 任务理解与评分映射

> 依据：《四足机器人 Lite3 实践任务书（修订版）》第五章「任务二　恢复运控」及第八章考核办法。
> 本文件只回答一件事：**任务书要什么、我们用什么交付物对应、拿什么证据证明。**

## 1. 任务边界

| 项目 | 任务书要求 | 本项目边界 |
|---|---|---|
| 平台 | 不带激光雷达的 Lite3 一台 | 仿真为主；实机仅做保护条件下的受控测试 |
| 核心内容 | 摔倒检测 + 恢复决策：状态机触发与起身动作调用 | 不训练分类模型，不重新设计起身动作 |
| 起身动作 | 复用平台已有能力（RL SDK 内置 `StandUp`） | 决策层负责「何时、在什么条件下」调用 |
| 验证 | 仿真构造翻倒姿态；实机须保护 | 9 次翻倒 + 3 次受阻，全流程自动化记录 |
| 交付 | 判定依据、恢复逻辑、仿真验证 | 代码 + 参数 + 原始数据 + 未剪辑视频 + 报告 |

**明确不做**：端到端模型训练、强化学习策略设计、完整工程平台搭建、产品级可靠性。

## 2. 最低完成标准（合格线）

任务书 8.4 对任务二的要求：

1. 3 种翻倒姿态共 9 次测试中，**正确判定 ≥6 次**，误报 **≤1 次**；
2. 判定后**先进入安全状态再尝试起身**，顺序正确 **≥6 次**；
3. **起身成功 ≥6 次**；
4. 起身受阻时**停在安全状态并给出提示**。

以上为必须守住的下限。本方案在此基础上按优秀档设计。

## 3. 评分项逐条映射

### 3.1 摔倒检测（25 分）

| 档次 | 任务书条件 | 本方案 |
|---|---|---|
| 合格 | 9 次正确 ≥6，误报 ≤1 | 已完成即达标 |
| 良好 | 正确 ≥8，误报 0 | — |
| 优秀 | 9 次全部正确，判定时延 ≤2 s | 目标：9/9，时延 ≤0.5 s |

**实现**：IMU 姿态主判据 + 关节姿态/角速度辅助确认 + 驻留时间 + 回差。
**证据**：`data/raw/trials.csv` 中每次的 `t_fall`、`t_detect`、`latency_ms`、`detected`；3 段正常小跑无误报记录。

### 3.2 恢复流程（25 分）

| 档次 | 任务书条件 | 本方案 |
|---|---|---|
| 合格 | 先安全后起身，顺序正确 ≥6 | FSM 强制先 `DAMPING` |
| 良好 | 顺序正确 ≥8 | — |
| 优秀 | 9 次正确，能说明每步切换条件 | 转移表 + 时间戳 + 答辩说明 |

**实现**：`NORMAL → DAMPING → ASSESS → STANDUP → VERIFY → NORMAL / SAFE_FAULT`。
**证据**：每次试验记录 `t_damping` 与 `t_standup_cmd`，脚本断言 `t_damping < t_standup_cmd`；`docs/02-state-machine.md`（待写）列出每个转移的进入/退出条件。

### 3.3 起身完成（25 分）

| 档次 | 任务书条件 | 本方案 |
|---|---|---|
| 合格 | 成功 ≥6 | 必须守住 |
| 良好 | 成功 ≥8 | 争取 |
| 优秀 | 9/9，平均耗时 ≤15 s | 受平台起身包络限制，不承诺（见 `docs/08-feasibility.md`） |

> 预研结论：平台 `StandUp` 只能从趴/坐姿起身，90° 全侧翻/仰翻无法自恢复。正式 9 次采用可恢复姿态，预计前翻 3/3、侧翻 3/3、后翻 0–3/3；起身耗时目标 ≤10 s（站立轨迹 4 s + 稳定判定 1 s）。

**成功判据**（同时满足并保持 1 s）：
- `|roll| < 10°`、`|pitch| < 10°`；
- 躯干高度恢复（仿真）或关节角回到站立包络（实机）；
- 四足支撑、关节速度收敛。

**证据**：`t_standup_cmd` 到 `t_upright` 的耗时统计；视频逐次可核对。

### 3.4 失败与超时（15 分）

| 档次 | 任务书条件 | 本方案 |
|---|---|---|
| 合格 | 受阻 3 次中 ≥2 次停安全状态并提示 | — |
| 良好 | 3 次均停安全状态并提示 | — |
| 优秀 | 3 次且不出现无限重试 | 上限 2 次尝试 + 故障锁存 |

**策略**：
- 单次起身超时 `20 s`；
- 最多 `2` 次尝试，间隔 `2 s`；
- 仍失败 → `SAFE_FAULT`：保持阻尼/待机，发布故障码与提示，**只能人工复位**；
- 1 分钟内恢复超过 3 次 → 直接 `SAFE_FAULT`（防反复触发）。

**证据**：3 次受阻测试的 `attempts`、`final_state`、`fault_code`、提示日志；视频包含一次完整异常处理。

### 3.5 参数依据（10 分）

| 档次 | 任务书条件 | 本方案 |
|---|---|---|
| 合格 | 给出判定阈值取值 | `config/recovery.yaml` |
| 良好 | 给出实测分布与阈值来源 | 正常小跑 vs 翻倒姿态的 roll/pitch 分布图 |
| 优秀 | 给出回差与持续时间的标定数据 | 二维扫描表 + 迟滞实验 + 选择理由 |

**标定内容**：
- 阈值扫描：`roll/pitch` 30°–70°，步长 2.5°；
- 驻留扫描：`0.1–1.0 s`，步长 0.1 s；
- 回差扫描：`0/5/10/15°`；
- 指标：检出率、误报数、平均时延、起身期间重复触发次数；
- 输出：`data/calibration/sweep.csv`、`data/calibration/thresholds.md`、分布图。

**证据**：`docs/05-calibration.md`（待写）记录完整实验设置与结论。

## 5. 验收自查表（演示前逐项打勾）

- [ ] 9 次测试按「前翻 / 后翻 / 侧翻各 3 次」分配并记录姿态构造方式
- [ ] 每次都有 `t_fall → t_detect → t_damping → t_standup → t_upright` 时间戳
- [ ] 9 次中先安全后起身的顺序全部正确
- [ ] 误报统计覆盖至少 3 段正常小跑（每段 ≥60 s）
- [ ] 3 次受阻测试均以 `SAFE_FAULT` 结束，且尝试次数 ≤2
- [ ] 故障提示可见/可听/有日志，复位流程明确
- [ ] 阈值、回差、驻留时间的标定表与图齐全
- [ ] 视频未剪辑，能看清状态切换与提示
- [ ] 代码、数据、配置已冻结并打 tag
